> 冻结日期：2026-08-16  
> 前置稳定基线：`v0.3.11-stable`

# 一、最终结论

**v0.4 战斗系统升级阶段验收通过，正式冻结为 `v0.4.9-stable`。**

本阶段已经把原有“能完成事件战斗”的简易回合制底层升级为可继续承载后续内容的基础战斗框架。等级、境界、速度、武学、内力、敌方 AI、状态和武学熟练度已经进入统一战斗演算；第一季剧情、事件系统、旧存档和 PWA 发布链保持兼容。

冻结后，除阻断性 Bug 外，不再回头重构 v0.4 已验收的战斗核心。后续常规内容扩展应优先通过角色、敌人、武学和状态数据完成。

# 二、阶段验收记录

## 阶段 A：战斗基线审计与回归锁

**通过。**

已建立独立 `tests/battle-smoke.mjs`，锁定：

- 1v1；
- 2v2；
- 治疗；
- 玩家动态武学；
- 胜利；
- 失败。

第一季新存档 Smoke 保持通过。

## 阶段 B：动态战斗属性

**通过。**

已建立统一 combatant 构造层。主角实际读取：

- 等级；
- 境界；
- 基础角色属性；
- 已学武学。

等级与境界已经真实影响最大气血、攻击、防御、速度与内力容量。

真机验收曾确认 Lv.7 · 大星位主角显示为动态属性，不再使用旧静态 Lv.1 数值。

## 阶段 C：统一行动顺序与普通攻击

**通过。**

- 全体单位按有效速度/先手值进入统一行动队列；
- 高速敌人可先手；
- 明显更快的单位仍可压过境界先手修正；
- 所有单位具备独立普通攻击；
- 普通攻击不再由武学占位。

真机已确认普通攻击入口和速度行动顺序生效。

## 阶段 D：内力与武学消耗

**通过。**

- 单场战斗拥有 `maxQi / qi`；
- 战斗开始满内力；
- 武学按数据配置真实消耗内力；
- 内力不足时无法施放，且不扣血、不推进回合；
- 普通攻击回复固定内力；
- 战斗 UI 显示当前/最大内力。

未修改存档结构，`SAVE_VERSION` 保持 2。

## 阶段 E：敌方境界、武学与基础 AI

**通过。**

第一季主要敌人已拥有：

- 境界；
- 武学；
- 内力；
- 数据驱动 AI 参数。

敌方 AI 支持：

- 有可用武学时择机施放；
- 内力不足时普通攻击；
- 低血量时按配置考虑治疗；
- 不施放无法支付消耗的技能。

敌人行为差异通过数据配置完成，没有按敌人名字在核心战斗流程里大面积写死。

## 阶段 F：境界压制基础版

**通过。**

境界差已经温和影响：

- 伤害；
- 减伤；
- 先手；
- 控制抗性接口。

同境界无额外压制；高境界具有可感知优势，但没有形成“高一境界即绝对碾压”的硬规则。

## 阶段 G：通用状态框架

**通过。**

已建立通用状态对象与生命周期，至少支持：

- 中毒；
- 控制/定身；
- 护盾。

状态能够：

`技能施加 → 回合中生效 → 正确扣持续时间 → 到期移除 → 日志记录`

护盾会先于气血承伤；控制会实际跳过行动；中毒会持续造成伤害。

## 阶段 H：武学与熟练度进入战斗计算

**通过。**

- 玩家武学熟练度被带入战斗对象；
- 熟练等级对武学产生温和实战增益；
- `折风剑式` Lv.2 相比 Lv.1 有可测但不过度的伤害提升；
- `realmRequirement` 已成为真实施放条件；
- 境界不足时不会扣内力、不会伤敌、不会推进回合。

## 阶段 I：战斗 UI 最小适配

**通过。**

手机战斗界面现在明确显示：

- 当前行动者；
- 本回合行动顺序；
- 单位境界；
- 当前/最大气血；
- 当前/最大内力；
- 当前状态；
- 技能威力；
- 熟练度；
- 内力消耗；
- 禁用原因（内力不足 / 境界不足）；

曾使用非存档、非剧情的临时 UI 验收入口完成真机验收；验收通过后，该临时入口已从正式代码中删除。

# 四、冻结后的架构约束

v0.4 冻结后，后续开发必须遵守：

1. 新增普通敌人优先修改敌人数据，不为单个敌人在 `battle.js` 添加专属分支；
2. 新增武学优先通过 `SKILLS` 数据配置威力、消耗、状态等；
3. 新增常规状态优先扩展状态定义/通用状态接口；
4. 不因单一剧情战斗重写行动队列、内力系统或境界压制核心；
5. 每次后续阶段发布继续保留 Battle Smoke 与第一季 Smoke；
6. 除阻断性 Bug 外，v0.4 战斗核心视为冻结基线。
