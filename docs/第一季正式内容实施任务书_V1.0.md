> 文档性质：第一季内容生产阶段的开发执行文档

# 0. 文档权重与开发纪律

本任务书自建立后，作为“第一季正式内容生产阶段”的当前执行主线。

执行权重：

1. 《不良人：江湖行》游戏开发计划书 V1.0
2. 本任务书
3. v0.2 技术实施任务书与 v0.2 冻结报告
4. 聊天中的临时想法、功能建议和偏好

聊天中的临时需求默认进入需求池，不自动插队。

只有用户明确提出以下指令时，才允许改变本任务书顺序：

- 修改任务书
- 调整开发顺序
- 提高某功能优先级
- 现在先做某项内容
- 暂停当前阶段并切换到另一阶段

每次开始新开发内容前必须先判断：

> 它是否属于当前阶段？

若不属于，则不得提前开发。

如果发现任务书存在遗漏、冲突或技术阻断：

1. 先停止跨阶段开发；
2. 明确指出问题；
3. 给出修改建议；
4. 未得到明确变更指令前，不自行重排路线。

# 一、第一季内容阶段总目标

《游戏开发计划书 V1.0》要求：

- 主线不逐集复刻动画；
- 每季抽取约 6～10 个核心大事件；
- 玩家在主线之间仍可自由探索、练功、做支线、奇遇、人物互动、武学获取；
- 声望负责推动世界事件与主线大事件；
- 等级、境界、声望彼此独立；
- 大历史节点基本遵循原作，但玩家可以影响事件过程、人物关系和部分结果；
- 隐藏事件不应全部公开条件；
- 重点人物不能只是“抽卡角色”，应有关系、专属事件、隐藏剧情等长期内容。

第一季正式内容阶段的完成目标因此定义为：

> 玩家从全新存档进入渝州后，可以在自由活动中成长、积累声望、接触人物和隐藏事件，并依次卷入第一季核心大事件；主线之间不形成单纯的“点任务→打一场→下一任务”流水线，最终可以完成第一季终局，同时存在可错过、可隐藏、可因关系和成长状态变化而不同的内容。

# 二、版本策略

v0.2.8-stable 继续作为基础框架冻结基线。

第一季正式内容开发统一进入：

```text
v0.3.x
```

规则：

- 每完成一个可真机验收的内容阶段，可以递增 patch 版本。
- 不为单个文字小修频繁升大版本。
- 第一季全部硬性验收通过后，再确定最终的 `v0.3.x-stable`。
- v0.3 开发不得回头大规模重构 v0.2 State、存档、条件引擎、事件引擎。
- 如果内容生产确实暴露框架缺陷，必须先作为“框架例外”提出，不得顺手重构。

# 三、第一季核心大事件槽位

上位计划已经给出第一季示意结构，本任务书固定为以下 8 个核心大事件槽位：

1. 渝州初入江湖
2. 李星云相关事件
3. 玄冥教行动扩大
4. 幻音坊介入
5. 通文馆介入
6. 龙泉相关线索
7. 多方势力争夺
8. 第一季终局

对应现有章节骨架：

```text
s1_prologue
s1_yuzhou
s1_xuanming
s1_huanyinfang
s1_tongwenguan
s1_longquan
s1_finale
```

注意：

- “8 个核心大事件”不要求机械地一一对应 7 个 chapter。
- 李星云相关事件可以发生在 `s1_yuzhou` 或由 `s1_yuzhou` 向 `s1_xuanming` 过渡。
- “多方势力争夺”可以作为 `s1_longquan → s1_finale` 的桥接大事件。
- chapter 表示世界阶段，不代表该阶段只能存在一个任务。
- 同一 chapter 必须允许同时存在主线、人物事件、支线、隐藏事件和自由活动。

# 四、正式内容生产的证据规则

当前项目来源只明确了第一季的大事件结构，没有提供完整的第一季逐事件剧情资料。

因此正式内容禁止仅凭模型记忆直接编写原作关键事实。

正式事件分两类：

## A. 原作历史节点

包括但不限于：

- 原作人物首次重要介入；
- 原作势力行动；
- 原作关键冲突；
- 原作关键地点；
- 龙泉相关核心进展；
- 第一季终局的大历史结果。

这些内容在正式编码前必须先进入：

```text
docs/第一季原作大事件基准表.md
```

基准表至少记录：

```text
事件名称
对应阶段
涉及人物
涉及势力
发生地点
前置大事件
事件结果
哪些结果必须保持原作方向
哪些过程允许玩家介入
资料依据/核对状态
```

未完成核对的关键原作事实，只能标记 `待校对`，不能直接写成正式游戏事实。

## B. 玩家原创内容

可以原创：

- 玩家如何进入事件；
- 玩家自己的支线；
- 自由练功与江湖挑战；
- 不改变原作核心结果的中间冲突；
- 原创 NPC；
- 原创隐藏地点；
- 原创奖励获得过程；
- 玩家与人物之间的原创互动；
- 不与原作冲突的可错过奇遇。

原则：

> 原作决定“大历史锚点”，玩家原创内容负责“玩家如何活在这段历史里”。

禁止：

- 复制动画原对白；
- 逐集复刻；
- 让玩家完全替代原作主角；
- 为了让玩家“爽”而随意改掉尚未批准修改的核心历史结果。

# 五、第一季内容密度标准

第一季正式版不能只有 8 个主线按钮。

全季目标内容结构：

## 1. 主线大事件

目标：

```text
8 个核心大事件
```

允许一个大事件拆成多个事件数据，但玩家体验上仍应属于同一个核心历史节点。

## 2. 人物事件

第一季优先人物：

- 李星云
- 蚩梦
- 女帝

降臣不因用户偏好而强行提前进入第一季；是否出现必须服从既定原作阶段和任务书。

全季至少形成：

```text
4～8 个有效人物事件
```

要求：

- 至少一部分事件受好感或 personalFlags 影响；
- 不要求所有事件都能在单周目看到；
- 同行状态与好感继续保持解耦。

## 3. 支线 / 奇遇 / 隐藏事件

全季至少形成：

```text
8～12 个非主线事件
```

其中至少：

- 2 个隐藏事件；
- 1 个低声望或特殊条件事件；
- 2 个使用组合条件的事件；
- 1 个可错过内容。

组合条件可以来自：

- 声望
- 境界
- 好感
- Flag
- 已完成事件
- 物品
- 地点
- chapter

禁止所有事件都只使用“完成前一个主线”作为条件。

## 4. 自由活动

主线未满足时，玩家仍必须有内容可做。

至少保留：

- 练功
- 江湖遭遇
- 人物互动
- 支线/奇遇中的一部分

重复活动应遵循上位计划的原则：

> 可以重复，但收益有限。

正式内容阶段不得长期保留“无限无代价点击 +5 修为”作为最终玩法。

## 5. 战斗

不规定“每个主线必打一场”。

原则：

- 只有剧情和玩法确实需要时才进入战斗；
- 战斗必须由事件引擎调用；
- 结果必须回传事件系统；
- 奖励继续由事件数据结算。

第一季应包含若干有意义的战斗节点，但禁止为了“看起来像游戏”机械堆战斗。

# 六、声望与成长节奏

上位计划给出的第一季声望只是示意区间：

```text
0      无名小卒
50     渝州开始有人认识玩家
120    玄冥教事件扩大
200    第一次大型势力事件
300    第一季后期
400    第一季终局开启
500+   第二季江湖正式展开
```

本任务书规定：

1. 第一季正式填充时可以调数值，但必须以真实游玩节奏为依据。
2. 不允许为了赶进度随意给单个事件巨额声望。
3. 声望是主线主要门槛，但不是唯一门槛。
4. 第一季终局不得只判断 `reputation >= X`，至少还要有必要的大事件完成状态。
5. 部分隐藏事件允许要求低声望。
6. 等级和境界不能被当作剧情计时器。

境界推荐仍遵循上位计划：

```text
第一季前期：无品～小星位
第一季中后期：中星位～大星位
```

但不设置绝对硬锁；允许玩家提前变强或低境界挑战。

# 七、数据与代码边界

v0.2 已冻结，第一季正式内容优先通过数据完成。

优先修改：

```text
src/events.js
事件相关数据文件（后续如有必要再拆分）
角色/敌人/地点/物品/武学数据
docs/
```

默认不得大改：

```text
src/state.js
src/conditions.js
通用事件引擎核心接口
存档版本结构
Service Worker 更新架构
app.js 主流程
```

允许的正常内容操作：

- 新增事件；
- 新增条件组合；
- 新增现有类型的奖励；
- 新增地点解锁效果；
- 新增人物好感与 personalFlags；
- 新增角色、敌人、物品、武学数据；
- 替换骨架占位文案；
- 调整经过测试证明不合理的内容数值。

如果正式内容需要一个当前引擎完全不支持的效果，例如：

- 学会新武学；
- 复杂分支选择；
- 特殊战斗状态；
- 新型事件结果；

必须执行“框架例外流程”：

1. 先证明现有数据结构无法完成；
2. 明确最小新增接口；
3. 评估是否影响旧存档；
4. 不顺手重构其它模块；
5. 修改后重新跑 v0.2 核心回归检查。

# 八、Flag 使用纪律

继续执行 v0.2 规范：

Flag 只表示无法被已有结构清晰表达的世界事实。

允许：

```text
helped_huanyinfang
spared_xuanming_scout
found_dragon_spring_clue
```

不允许：

```text
story1
story2
step4
doneA
```

已经可以由以下结构表达的内容，不再重复建 Flag：

- 事件完成：`events.completed`
- 人物相识：`relationships`
- 地点解锁：`unlockedLocations`
- 当前阶段：`world.chapter`

# 九、阶段 A：第一季原作大事件基准锁定

## 目标

在写正式第一季剧情前，先固定第一季的大历史锚点，避免开发过程中不断改剧情方向。

## 本阶段只做

建立：

```text
docs/第一季原作大事件基准表.md
```

覆盖 8 个核心大事件槽位：

1. 渝州初入江湖
2. 李星云相关事件
3. 玄冥教行动扩大
4. 幻音坊介入
5. 通文馆介入
6. 龙泉相关线索
7. 多方势力争夺
8. 第一季终局

## 本阶段禁止

- 不改游戏代码；
- 不写大量正式对白；
- 不做第二季；
- 不提前做美术；
- 不凭模糊记忆填关键原作事实。

## 完成标志

**8 个核心大事件均具有明确“原作锚点 / 玩家可介入空间 / 不可随意改变结果”的定义，且没有关键事件处于完全未知状态。**

未达到完成标志，不进入阶段 B。

# 十、阶段 B：序章 / 渝州篇正式化

对应：

```text
s1_prologue
s1_yuzhou
```

核心大事件：

- 渝州初入江湖
- 李星云相关事件

## 本阶段任务

1. 将现有序章测试味内容改为正式内容。
2. 保留可用的“驿道疑云”等既有机制，但重新审查其剧情定位。
3. 建立玩家原创主角进入第一季江湖的合理路径。
4. 建立第一批正式自由活动。
5. 建立第一批正式支线/隐藏事件。
6. 处理蚩梦早期人物互动。
7. 按基准表接入李星云相关大事件。
8. 让玩家通过自由活动、事件和战斗自然累积第一批声望。

## 本阶段最低内容包

至少：

- 2 个核心主线大事件槽位落地；
- 2 个非主线事件；
- 1 个人物事件；
- 1 个隐藏/条件事件；
- 1 个可重复但收益受控的自由活动；
- 至少 1 个事件可以通过不同玩家状态产生不同可见内容或触发时机。

## 完成标志

全新存档可以：

```text
进入渝州
→ 自由活动
→ 推进正式序章
→ 参与渝州核心事件
→ 接入李星云相关大事件
→ 达成进入玄冥教篇的世界条件
```

同时：

- 不能只靠连续点击“当前任务”完成全部流程；
- 主线未满足时仍有可玩内容；
- 至少存在一个玩家可能错过或晚触发的事件。

未验收，不进入阶段 C。

```text
s1_longquan
→ s1_finale
```

核心大事件：

- 多方势力争夺
- 第一季终局

7. 为第二季只留下世界状态接口，不开发第二季正式内容。

从全新存档出发，玩家可以完成正式第一季终局；不同游玩路径至少在部分人物/隐藏内容/过程反馈上存在差异，并且不存在必须按唯一按钮链连续点击才能通关的设计。

未验收，不进入阶段 H。

# 十六、阶段 H：第一季自由内容与成长回填

本阶段不是“随便加内容”，而是对前面七个阶段做结构性补齐。

## 检查目标

### 1. 自由度

检查每个主线阶段：

- 主线未触发时是否有事可做；
- 是否存在练功/遭遇/人物互动/支线中的至少一种；
- 是否过度依赖“当前任务”按钮。

### 2. 四轴利用

检查全季是否真正使用：

- 声望
- 境界
- 武学
- 人物关系

若某一轴在第一季几乎没有实际作用，应提出缺口，但不得擅自重构底层。

### 3. 隐藏内容

检查：

- 是否至少 2 个真正隐藏事件；
- 是否有组合条件；
- 是否有可错过内容；
- 是否没有把所有触发条件直接告诉玩家。

### 4. 武学内容

上位计划明确第一季正式内容阶段应逐步填充武学。

因此本阶段检查：

- 第一季是否至少存在有意义的武学获得/成长内容；
- 武学是否服务于探索和成长，而非仅是静态技能列表。

如果当前事件引擎缺少必要的“获得武学”等效果：

> 走“框架例外流程”，不得顺手大改底层。

### 5. 奖励与数值

检查：

- 是否存在刷某个无限按钮即可远超正常成长的问题；
- 声望是否膨胀；
- 银两是否失去意义；
- 第一季正常玩家是否大致落在计划推荐境界；
- 提前探索型玩家能否更强，但不至于完全破坏主线。

## 完成标志

第一季不再只是“完整主线”，而是具备基本群侠传式自由江湖体验。
