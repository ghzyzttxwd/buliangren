# 三、素材来源总策略：网上找优先，生成兜底

这是本阶段固定策略。

## 优先级 1：现有可明确使用的网络素材

优先寻找：

- 明确允许复用 / 修改的图片；
- CC0 / Public Domain / 开放授权素材；
- 可商用或可用于项目的免费素材；
- 可复用纹理、山水、烟雾、光斑、粒子、纸张、水墨等通用美术资源；
- 已经存在且质量足够的角色 / 场景素材，在其授权条件明确允许时使用。

正式入库前必须记录：

```text
sourceUrl
sourceName
license / usage note
retrievedAt
localFile
purpose
```

禁止图片热链。正式使用资源必须下载到仓库或后续明确的资源存储位置。

## 优先级 2：网络图片作为视觉参考

对于原作官方立绘、宣传图、截图、游戏画面等：

- 可以用于研究人物造型、服饰、配色、构图、技能演出；
- 但“网上能看到”不等于“可以直接重新分发”；
- 来源 / 授权不明确时，不直接视为最终可打包资源。

这类图片可以作为：

- 人物外观参考；
- 战斗构图参考；
- 地图气氛参考；
- 技能特效参考；
- AI 生成时的设计参考。

## 优先级 3：已有资源二次加工

对明确可用的素材优先采用：

- 裁切；
- 抠透明背景；
- 尺寸统一；
- WebP / PNG 转换；
- 亮度 / 对比度轻调；
- 边缘柔化；
- 轻量水墨化；
- 合理叠加 CSS 特效。

目标是减少无意义重新生成。

## 优先级 4：AI 生成

只有出现以下情况才生成：

- 网上没有合适素材；
- 素材授权无法确认；
- 主角为原创角色，没有现成正式立绘；
- 需要统一风格的战斗站姿；
- 需要特定 Cut-in 构图；
- 需要原创地图背景；
- 需要难以通过 CSS / 免费粒子实现的特殊效果。

用户已明确偏好：

> 能网上找到就先找，确实需要生成时再生成。

因此本阶段不得为了“统一风格”一上来批量生成几十张图。

# 五、图片技术规范

## 1. 默认格式

优先：

```text
WebP
```

需要透明边缘且 WebP 不合适时使用 PNG。

不默认使用未经压缩的大 JPG / PNG 原图直接上线。

## 2. 手机优先

所有资源以 320～520px 主界面为主。

不得为了“高清”把大量 4K 图片塞进 PWA。

建议目标：

### 人物主立绘

```text
长边 900～1400px
```

### 战斗站姿

```text
长边 500～900px
透明背景
```

### 大招 Cut-in

```text
短边至少约 700px
优先竖屏构图
```

### 场景背景

```text
约 1080×1920 或相近竖屏比例后压缩
```

实际允许根据图片内容调整，不把像素尺寸写死。

## 3. 单资源大小

优先目标：

- 普通人物 / 背景：数百 KB 级；
- 小特效：尽量 < 200KB；
- 大招 Cut-in：在观感和体积间平衡；
- 不允许单张普通素材动辄数 MB 而没有理由。

## 4. 加载

非首屏资源采用延迟加载 / 按需加载。

关键首屏资源允许预加载，但不得一次预载全游戏美术。

## 5. 降级

任何美术资源加载失败时：

- 页面不能白屏；
- 战斗不能卡死；
- 必须回退到现有文字 / 渐变 / 占位视觉；
- 业务逻辑不能依赖图片是否成功加载。

# 六、战斗视觉方向

用户已明确：

> 战斗希望接近《新倚天屠龙记》那种“人物真正站在战场里、放大招时角色成为画面视觉主体”的感觉，但不要求 1:1 复刻骨骼动画。

因此 v0.7 战斗美术方向固定为：

## 普通状态

```text
我方角色站位
vs
敌方角色站位
```

人物真实出现在战场区域，而不是只有信息卡。

第一版不要求 Spine / Live2D / 重骨骼。

允许通过：

- PNG / WebP 战斗站姿；
- CSS translate / scale；
- 短距离前冲；
- 轻微受击位移；
- 震屏；
- 闪白；
- 残影；
- CSS filter；
- 轻粒子；

实现“有动作感”。

## 普通攻击

最低表现：

```text
行动角色强调
→ 短位移 / 攻击动作
→ 命中反馈
→ 飘字 / 震动
→ 回位
```

## 普通武学

在普攻上增加：

- 技能名；
- 一种对应的轻量特效；
- 更明显的动作 / 屏幕反馈。

## 核心武学 / 绝招

固定采用 Cut-in 结构：

```text
战场压暗
→ 角色放大 / 全屏或大面积 Cut-in
→ 武学名出现
→ 核心特效爆发
→ 命中 / 震屏 / 闪白
→ 返回正常战场
```

人物在此阶段必须明显“变大”，成为整个手机屏幕的视觉主体。

这就是 v0.7 对《新倚天屠龙记》式演出的正式落地定义。

# 八、阶段 B：第一批重点人物主立绘

## 第一批角色

优先顺序：

1. 玩家原创主角；
2. 蚩梦；
3. 女帝；
4. 第一季当前实际出现 / 同行的其他核心人物。

原则：

- 不因为未来第二季会出现就提前做大量人物；
- 降臣等未进入当前第一季正式内容的人物，不因用户偏好提前塞入第一季页面。

## 素材策略

每个角色依次：

```text
网上搜索可用素材
→ 判断能否正式使用
→ 能用则本地化
→ 不能用则作为参考
→ 确实缺资源才生成
```

## 页面接入

主立绘优先进入：

- 队伍页；
- 人物相关 Sheet / 剧情节点；

不得为了立绘改人物系统逻辑。

让战斗第一次出现真实人物主体。

# 十、阶段 D：核心武学 Cut-in / 大招演出

## 目标

实现用户要求的“角色突然变大、绝招占据画面”的战斗表现。

第一批只选少数高价值武学，不做全技能。

优先：

- 主角当前核心武学；
- 蚩梦代表技能；
- 女帝代表技能；
- 第一季关键敌方 / Boss 代表技能（若当前内容存在）。

## 每个 Cut-in 至少包含

- 角色大幅图；
- 技能名；
- 背景压暗；
- 进入 / 退出动画；
- 命中反馈；
- reduced-motion 降级；
- 可在低性能设备上关闭或简化复杂效果的接口预留。

不做：

- 长视频 CG；
- 3D；
- 高成本 Spine 骨骼全套；
- 每个普通技能都 Cut-in。

# 十一、阶段 E：第一批技能与状态特效

## 范围

优先制作可复用效果类型：

- 剑光；
- 刀光；
- 拳风；
- 毒雾；
- 蛊；
- 治疗；
- 护盾；
- 控制；
- 命中闪光；
- 受击反馈。

原则：

> 先做“效果类型”，再让多个技能复用；不要每个技能一套独立素材。

优先级：

```text
CSS / SVG / Canvas 可解决
→ 可复用免费素材
→ 小型序列帧 / 图片
→ 最后才生成专用特效图
```

# 十四、阶段 H：性能、PWA 缓存与资源回归

## 必验

- 首屏加载不因图片明显失控；
- 图片失败有回退；
- 320 / 360 / 390 / 430 / 520px 不破版；
- PWA 更新后新资源可刷新；
- 老缓存不会长期卡住旧图；
- 战斗资源加载不阻断战斗；
- reduced-motion 可降级；
- Android 手机连续切换多个页面不出现明显内存异常；
- 不出现图片把页面撑出横向滚动。

资源总量达到需要时再决定是否做进一步拆包 / CDN / 外置资源，不提前引入复杂构建系统。

# 最终判定

v0.7 的完成标准不是“仓库里多了很多图片”。

真正完成标准是：

> **人物、战斗、绝招、技能和场景第一次形成统一且可扩展的正式视觉层；图片资源有清晰来源、有稳定加载与降级机制、不会破坏现有业务逻辑，并且玩家在手机上能明显感受到从网页原型向真正武侠 RPG 的视觉跃迁。**
