# 《不良人：江湖行》v0.6 UI / UX 验收冻结报告

> 冻结版本：v0.6.7-stable  
> 前置基线：v0.5.7-stable  
> 存档版本：SAVE_VERSION 2  
> 冻结日期：2026-08-17  
> 冻结依据：《游戏开发计划书 V1.0》与《v0.6 UI / UX 优化实施任务书 V1.0》

## 一、冻结结论

v0.6 UI / UX 优化阶段 A-J 已完成。

本阶段仅对信息架构、交互路径、响应式、组件一致性与视觉层级进行优化，没有推翻 State v2、v0.4 战斗核心或 v0.5 装备与物品系统。

游戏正式冻结为：

`v0.6.7-stable`

作为后续美术资源与战斗演出阶段的稳定回退基线。

## 二、已完成阶段

### Stage A：UI 基线审计与回归锁

- 建立 UI smoke；
- 锁住五项导航、顶部资源、地点 / 事件 / 装备 / 使用 / 商店 / 战斗等关键入口；
- 建立 UI 基线审计文档；
- 保持 v0.5 inventory、battle、season1 回归。

### Stage B：全局 Design Tokens 与应用壳

- 统一背景、面板、文字、金色强调、禁用 / 危险状态；
- 统一按钮、卡片、Sheet、Toast、底栏、顶部资源区；
- 保持业务数据与存档不变。

### Stage C：世界首页与节点地图 UX

- 首页直接展示当前阶段与下一步；
- 第一季通关档明确显示“无强制主线”；
- 成长信息压缩为摘要；
- 地图节点改为数据坐标，不再依赖 CSS nth-child；
- 地点状态统一为有事件 / 可进入 / 未解锁。

### Stage D：队伍与武学页面信息重构

- 队伍页统一角色身份、同行状态、攻防速、主角境界 / 修为 / 体力、关系与锁定信息；
- 武学页统一熟练度、威力 / 治疗、内力消耗、境界要求、简介；
- 修复角色占位字“侠 / 梦 / 岐 / 臣”等在手机上被裁切的问题，并加入回归锁。

### Stage E：行囊、装备、物品使用与商店 UX

- 名称 / 数量、状态、属性、特殊语义、操作按钮重新分层；
- 装备 / 卸下 / 使用 / 研读操作位置统一；
- 商店银两、单价、持有量、购买状态更清楚；
- 未修改 v0.5 装备、消耗品、秘籍或购买规则。

### Stage F：战斗 UI / UX 重构

- 当前行动角色成为第一视觉焦点；
- 行动顺序独立展示；
- 明确我方 / 敌方；
- 气血、内力、境界、状态继续可见；
- 普攻 / 武学 / 战斗物品前置于日志；
- 不可用原因继续展示；
- 胜负结果独立收束；
- 采用独立 battle UI 呈现层，未修改 battle.js 演算规则。

### Stage G：记录、设置、空状态与交互反馈

- 记录页层级整理；
- 自动存档、版本与 SAVE_VERSION 信息明确；
- 重置存档单独归入危险操作区，并保留二次确认；
- 空行囊、无事件、资源已满、银两不足、禁用操作等状态统一文字反馈；
- Toast 区分成功 / 失败 / 普通提示。

### Stage H：响应式、小屏与触控专项

按任务书对以下宽度建立专项规则与自动检查：

- 320px
- 360px
- 390px
- 430px
- 520px

重点加固：

- 顶部资源区；
- 底部导航与安全区；
- Sheet 可达性；
- 地图节点；
- 战斗操作；
- 长角色名 / 武学名 / 物品名；
- 44px 触控目标；
- 页面横向溢出风险。

### Stage I：v0.6 自动化总回归

建立统一入口 `tests/v06-ui-regression.mjs`，收束 A-H UI 验证。

最终固定 CI 顺序：

`static → v0.6 UI regression → v0.5 inventory regression → battle smoke → season1 smoke → Pages`

## 三、Stage J 手机真机总验收

用户使用现有手机环境和当前旧档对 v0.6.7 进行合并真机验收。

此前阶段已分别确认：

- 世界首页 / 地图可用；
- 队伍 / 武学信息可读；
- 角色占位字裁切问题已修复；
- 行囊与商店操作正常；
- 页面没有明显横向溢出或阻断操作问题。

在 Stage G-I 合并完成后，用户于 2026-08-17 对最终 v0.6.7 总体界面反馈：

> “没啥问题。”

据此，Stage J 记为真机总验收通过。

若第一季通关旧档不存在可直接触发的战斗节点，不人为新增测试剧情；战斗 UI 与行为由 battle UI smoke、battle baseline 和 season1 smoke 继续锁定。

## 四、存档与兼容策略

- `SAVE_VERSION` 继续保持 2；
- v0.6 未新增必须持久化的 UI 状态；
- 不因布局、颜色、当前页面、Sheet 或 CSS token 升级存档结构；
- v0.5.7-stable 第一季旧档继续作为主要兼容基线。

## 五、冻结边界

v0.6 明确没有实现：

- 正式人物立绘；
- 战斗角色正式美术；
- 地图背景插画；
- 技能粒子特效；
- 大规模图片资源；
- BGM / 音效；
- 第二季正式剧情；
- 新武学 / 新装备 / 新物品扩充；
- 战斗规则重构；
- State / inventory / event 核心重构；
- React / Vue / Vite 等框架迁移。

用户提出的“参考《新倚天屠龙记》的战斗表现：角色进入战场、绝招时人物大幅放大 / Cut-in、配合技能特效”的方向，已作为**后续美术资源 / 战斗视觉演出阶段的核心需求**保留，不属于 v0.6 UI / UX 阶段，不在本冻结版本越界实现。

## 六、后续主线

按照现有开发计划，v0.6 UI / UX 完成并冻结后，下一主线进入：

**美术资源阶段。**

在正式制作美术资源前，应先建立对应技术 / 美术实施任务书，锁定：

- 人物立绘规格；
- 战斗站姿 / 角色素材规格；
- 绝招 Cut-in 规格；
- 技能特效规格；
- 地图背景规格；
- 资源命名、尺寸、压缩与加载策略；
- 手机性能预算；
- 自动回归与真机验收标准。

不得因为单个临时想法跳过任务书直接批量生成或接入正式美术。

## 七、最终状态

v0.6 UI / UX 优化满足任务书完成标准，正式冻结为：

`v0.6.7-stable`

后续若需要修改 v0.6 冻结 UI 基线或触碰 v0.4 / v0.5 冻结底层，必须先说明原因并通过对应自动化回归，不得在美术阶段顺手重构。
