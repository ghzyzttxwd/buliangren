# 二、当前 CSS 文件职责

## styles.css

负责：

- 全局颜色变量；
- app-shell；
- topbar；
- 资源条；
- 主页面；
- 通用卡片；
- bottom-nav；
- 队伍；
- 武学；
- 行囊；
- modal / sheet；
- 战斗；
- Toast；
- 手机安全区。

当前大部分视觉规则都集中在该文件。

## responsive.css

当前主要承担：

- 品牌区改为单列；
- 四项资源改为四列 grid；
- 资源文字溢出处理。

当前响应式覆盖范围较窄，后续阶段需要扩展为系统性小屏规则。

## world-map.css

负责世界节点地图。

当前实现特点：

- 固定高度；
- CSS 渐变模拟抽象地图；
- 地点节点绝对定位；
- 位置通过 `nth-child` 写死；
- ≤380px 单独微调部分节点。

该方案当前可用，但地点数量变化时维护成本高，是阶段 C 的重点优化对象。

# 四、当前 UI 优化目标

以下是技术审计得出的优化目标，不代表当前存在阻断级 bug：

1. 统一字号、间距、圆角、边框、按钮高度等 design tokens；
2. 统一五页标题、卡片和次级信息的视觉层级；
3. 顶部资源条在不同手机宽度下进一步稳定；
4. bottom-nav、Sheet、Toast 的状态反馈统一；
5. 世界页需要更明显区分“当前阶段 / 下一步 / 成长 / 地图”；
6. 地图位置不应继续依赖 `nth-child`；
7. 队伍和武学页需要提高扫读效率；
8. 行囊 / 商店操作按钮需要更统一；
9. 战斗界面需要把“当前行动”和“可操作区”提高到第一视觉层级；
10. 需要系统覆盖 320 / 360 / 390 / 430 / 520px；
11. 长名称、长描述和多状态需要统一防溢出策略；
12. 空状态、禁用状态、危险操作和失败反馈需要统一规范。

# 五、冻结底层：本阶段不得顺手重构

v0.6 UI / UX 阶段默认不得改写：

- State v2；
- SAVE_VERSION 2；
- 第一季事件条件 / 奖励；
- 人物关系规则；
- battle 战斗演算；
- combatant 属性构造；
- inventory State；
- ITEM_CATALOG；
- equipment；
- consumable；
- manual / fragment / quest / treasure / material 语义；
- shops 购买规则。

若 UI 暴露真实底层缺陷，必须单独证明并做最小修复。
