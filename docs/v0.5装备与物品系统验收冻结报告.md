# 二、本阶段已完成能力

## 1. 统一物品数据与真实行囊

- 建立统一 ITEM_CATALOG；
- 物品使用稳定 item id；
- 行囊读取真实 `state.inventory.items`；
- 旧存档未知物品继续兼容保留；
- 数量归零后不继续显示为可用物品；
- 负数物品在 normalize / 使用流程中受到保护。

正式物品类型已经固定为：

```text
equipment
consumable
manual
fragment
quest
treasure
material
```

## 2. 装备系统

装备槽：

```text
weapon
armor
accessory
```

已完成：

- 装备；
- 卸下；
- 同槽替换；
- 错误槽位拒绝；
- 未持有装备拒绝；
- 装备仍属于 inventory，equipment 只记录当前装备 ID；
- 装备属性通过 combatant 构造层进入战斗，不在 battle.js 中写装备特例。

支持的基础装备属性修正：

```text
attack
defense
speed
maxHp
maxQi
```

当前正式样例：粗布护腕，饰品位，防御 +2。

## 3. 消耗品

已完成通用 item effect 处理与场景约束。

当前正式样例：止血散。

- 战斗外：恢复 10 体力；
- 战斗中：恢复当前行动角色 25% 最大气血；
- 使用后真实扣库存；
- 战斗中使用占用一次行动；
- 资源已满时不浪费；
- 数量为 0 时禁止继续使用；
- 使用结果可正常保存。

## 4. 特殊物品语义

已完成：

- 秘籍：支持学习目标、境界门槛、是否消耗；
- 残卷：可直接通过 hasItem(count) 参与事件数量条件；
- 剧情道具：默认不可直接使用 / 出售；
- 宝物：保留数据驱动的独特效果接口；
- 材料：完成分类与持有语义，本阶段不实现锻造。

## 5. 商人与银两闭环

新增基础商人数据与购买接口。

当前正式商人：

```text
渝州药摊
```

当前商品：

```text
止血散：24 银
```

已形成最小经济闭环：

```text
获得银两 → 消费银两 → 获得物品
```

已完成：

- 商品数据配置；
- 银两校验；
- 银两不足拒绝；
- 购买后扣银两；
- 背包数量增加；
- 自动保存；
- 剧情道具与唯一宝物不进入普通购买逻辑。
